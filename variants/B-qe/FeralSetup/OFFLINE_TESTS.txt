v3.9.2 — form installation applies and verifies resource bindings

Lua 5.1 simulations cover both independent Numbers and QE packages:
- Full setup, three form pages, ordinary binding reapply and snapshot restore.
- /fs form repairs missing and legacy direct resource keys in every form.
  The regression fails on the previously published 3.9.1 code.
- Rejected or silently ignored bindings stop setup/form before bar changes
  or saved-snapshot replacement. Existing macro edits survive form placement.
- Native binding API rejects CMD- strings; Mac accepts canonical META chords;
  Windows receives no META binding writes, including Mac-snapshot recovery.
- Exact stale Mac cases: Cmd+C potion, Cmd+R old regeneration and old Cmd+1/2.
- Shared Alt parity, self/focus macro routing and modifier precedence.
- GetNumBindings excludes directly bound macros, matching the observed client.
- Resource/Shift+W recover through visible bar slots; legacy direct bindings on
  managed keys are also captured for backups/rollback.
- Human Moonfire/Wrath/Starfire/Hurricane and single Roots/Hibernate control pair.
- Preserved item slots report actual names, missing items, wrong action types,
  and unverified custom macros/mounts; contents are not silently replaced.
- Binding read-back/rollback, combat/cursor guards, personal edits, learned form
  indices, stealth fallbacks, macro lengths, levelling and guide-download ZIPs.

These are API simulations informed by the client's saved state and Blizzard's
binding utility, not a live-client test. Actual input delivery, casting, range,
line of sight, failed-cast autoUnshift and OS shortcuts still need in-game checks.
Reports identify item names/types; they do not infer every custom macro effect
or guarantee a preserved item is the right consumable. Installing files alone
does not update saved bars: follow README.txt's full setup steps.
